Product & Technology — The CardioAI Pro Engine

This is the actual, built system this financial model is built on — not a roadmap. Every capability listed below has been implemented and tested against a running backend, not just designed.

Core Orchestration

A 15-agent pipeline coordinates every reading that enters the system: ingestion → data quality scoring → FHIR R4 resource generation → risk inference → patient intake → longitudinal trend analysis → multi-modal fusion → diagnostic mapping → automation-tier policy → clinical reporting → alerting → care-continuum tracking → registry persistence. Real, tested end to end — not a diagram of an intended design.

Three Real Interfaces

Clinician Dashboard

  • 6-step EHR admission wizard (Personal, Demographics, Location, Insurance, Clinical, Vitals)
  • Real admit / discharge / readmit workflow
  • HL7 v2 ADT facility-transfer import
  • Full patient chart, longitudinal vitals, diagnostic order pipeline

Payer Portal

  • Real X12 837 claims parsing (reads the actual ISA envelope to detect real delimiters)
  • Real X12 834 enrollment parsing — true coverage data, not a claims-activity proxy
  • PMPM contract & billing, membership reconciliation, automatic proration
  • Data-gated cost-avoidance methodology and care management worklist

Main Engine Console

  • Live agent status and event log
  • Algorithmic bias/fairness audit with subgroup disparity metrics
  • DICOM ingestion, FHIR/HL7 sample viewers, automation-tier policy tester

Clinical Safety Design

Automation escalation is deliberately conservative: a single elevated reading cannot trigger urgent auto-escalation on its own — that requires both a confirmed, clinically-specific diagnosis code and high model confidence simultaneously. This structural gate is a design choice made and tested, not a claim.

Where This Model Is Honest About Its Own Limits

The underlying MACE risk-scoring model is a real, tested software pipeline running on a placeholder heuristic — not yet a clinically validated model. The infrastructure around it (ingestion, quality scoring, fusion, longitudinal tracking, billing, audit) is real and tested; the clinical scoring intelligence inside it is the next validation milestone. Clinical validation is now in progress through the Mayo Clinic Accelerate program — that work has started, but "in progress" means exactly that: the model is not yet validated, and this page does not claim otherwise until that work concludes.

Unit Economics — CAC & Payback

Computed from real inputs already in the source model — dedicated acquisition cost divided by contracts actually closed in that period, not a separately invented figure.

These LTV:CAC ratios are real arithmetic on real model inputs, but they are not representative unit economics — read the explanation below before citing them. They're this low-CAC because V7A's Year 1 sales cost is temporarily suppressed (4 reps at $35K each, capped below the founders' own reduced salaries, per the model's own notes) — not because customer acquisition is actually this cheap. The model itself flags that FY2028 reps revert to market rate.

How Enterprise and Payer were computed

Enterprise CAC = Y1 dedicated sales force cost ($140K, 4 reps × $35K) ÷ Y1 contracts signed (15) = $9,333. Payback = CAC ÷ monthly gross profit per contract ($800K × 70% ÷ 12 = $46,667/mo) ≈ 6 days. LTV:CAC = $2.24M CLV ÷ $9,333 CAC ≈ 240x.

Payer CAC = Y1 payer analytics team cost ($200K, one lead hired Q4 2027) ÷ Y1 contracts signed (10) = $20,000. At 25,000 high-risk members per contract and the Y1 blended $11.20 PMPM, annual gross profit per contract is $2.18M, so payback is under a month and a 4-year LTV:CAC (matching the Enterprise methodology's lifetime assumption) is roughly 437x.

For context, a fully-loaded, market-rate sales cost structure (the model's own "previous FY2027 run-rate" column: $800K enterprise sales force, $800K payer analytics team) would put Enterprise CAC at ≈$53,333 (LTV:CAC ≈ 42x) and Payer CAC at ≈$80,000 (LTV:CAC ≈ 109x) — still strong, but a more durable number than the Year-1-only figures above.

Consumer CAC/LTV is honestly not derivable from the source model as given. The model's promotional budget line ("ACC/AHA + digital + PR") is blended across segments, not split out as a consumer-specific paid-acquisition cost — so a clean CAC numerator doesn't exist without inventing a split the source data doesn't support. Separately, a multi-year consumer LTV needs a subscriber retention/churn assumption the model doesn't state; assuming one (e.g., "3-year average retention") would be a fabricated input dressed up as a computed metric. What IS real and computable: consumer gross profit per subscriber is $224.91/year ($24.99/mo × 12 × 75% margin) — shown as an annual unit economic, not extrapolated into an LTV that needs an assumption this model doesn't have.

11. Risk Factors

Stated directly, not softened, because a due-diligence reader will find these regardless:

  • Clinical validation is in progress, not complete. The risk-scoring model behind every segment in this plan is a real, tested software pipeline running on a placeholder heuristic — not yet a clinically validated model. Validation work is now underway through the Mayo Clinic Accelerate program; revenue in this plan assumes the product reaches a clinically credible state, which that program is a real step toward but has not yet delivered.
  • Regulatory clearance is not complete. FDA 510(k) Pre-Submission (Q-Sub) preparation is budgeted to begin pre-seed, with formal submission targeted Year 2 — this plan's revenue does not depend on clearance being achieved by a specific date, but a material delay would affect the Enterprise and Payer segments' sales cycles.
