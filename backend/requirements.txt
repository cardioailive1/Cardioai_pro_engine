# --- Known pip-audit findings, deliberately not yet actioned (as of 2026-10-10) ---
# starlette 0.38.6 (pulled in by fastapi==0.115.0): several known CVEs,
# fixed starting in 0.40.0/1.x. Not bumped yet because fastapi 0.115.0
# pins starlette<0.39 — fixing this means bumping fastapi to a version
# that allows a newer starlette, which is a bigger change needing a full
# regression pass across every route in api/routes.py, not a drop-in
# swap. Tracked, not ignored — see pip-audit's CI output for the current
# full list of specific CVE IDs.
# python-jose 3.5.0: CVE-2026-85394, no upstream fix version exists yet.
# The actual exploit needs the app to accept an attacker-supplied key at
# decode time; auth/security.py's jwt.decode() call explicitly pins
# algorithms=[JWT_ALGORITHM] (HS256 only), which is the documented
# mitigation — verified this app already does that, so treating this as
# a non-issue here rather than blocked-on-upstream.
# ecdsa (transitive, via python-jose): no fix version — a known,
# long-standing side-channel-timing finding upstream has not patched;
# commonly accepted as-is across the ecosystem for this reason.
